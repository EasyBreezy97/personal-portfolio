# Accessibility Skill

## Goal

Make the website usable by people with different abilities and input methods.

## Semantic HTML

Prefer semantic elements:

- header
- nav
- main
- section
- article
- footer
- button
- a

Do not use generic `<div>` elements when a semantic element is appropriate.

## Keyboard

All interactive functionality must be usable with a keyboard.

Check:

- Tab navigation
- Enter
- Space
- Escape where appropriate
- visible focus

Never remove focus outlines without providing an equivalent focus indicator.

## Links

Links must have meaningful accessible names.

Avoid vague links such as:

"Click here"

Prefer:

"View project"

## Buttons

Use `<button>` for actions.

Do not use links as buttons unless navigation is actually occurring.

## Images

Informative images need meaningful alt text.

Decorative images should not create unnecessary screen-reader noise.

## Headings

Maintain logical heading hierarchy.

Do not use headings purely for styling.

## Forms

Every form control should have an accessible label.

Errors should be understandable.

Do not rely exclusively on color to communicate errors.

## Color

Ensure sufficient contrast.

Do not communicate important information using color alone.

## Motion

Respect:

`prefers-reduced-motion`

Disable or reduce non-essential animation when requested.

## Mobile

Touch targets should be comfortable to use.

Avoid interactions that depend exclusively on hover.
